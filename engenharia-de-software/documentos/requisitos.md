# 📋 Documento de Requisitos do Sistema

# 1. Objetivo

Desenvolver um sistema web para gerenciamento de tarefas da empresa fictícia **TechFlow Solutions**, permitindo cadastrar, consultar, editar e excluir tarefas, aplicando conceitos de Engenharia de Software, metodologias ágeis, controle de versão, testes automatizados e integração contínua.

---

# 2. Escopo

O projeto contempla o desenvolvimento de um sistema web básico para controle de tarefas de uma startup de logística.

O sistema permitirá o gerenciamento das atividades por meio de operações de cadastro, consulta, edição e exclusão de tarefas, possibilitando o acompanhamento do andamento das atividades de forma organizada.

O desenvolvimento será realizado utilizando boas práticas de Engenharia de Software e versionamento com Git e GitHub.

---

# 3. Stakeholders

## Cliente

TechFlow Solutions (empresa fictícia)

## Usuários

- Administrador do sistema
- Colaboradores responsáveis pelo gerenciamento das tarefas

Adriano Mantoan

# 4. Requisitos Funcionais

O sistema deverá permitir:

### RF01

Cadastrar uma nova tarefa.

### RF02

Listar todas as tarefas cadastradas.

### RF03

Editar uma tarefa existente.

### RF04

Excluir uma tarefa.

### RF05

Alterar o status da tarefa.

### RF06

Pesquisar tarefas cadastradas.

### RF07

Exibir a data de criação da tarefa.

---

# 5. Requisitos Não Funcionais

O sistema deverá:

### RNF01

Ser desenvolvido utilizando Python e Flask.

### RNF02

Possuir interface web responsiva.

### RNF03

Utilizar controle de versão com Git.

### RNF04

Ser hospedado no GitHub.

### RNF05

Possuir testes automatizados.

### RNF06

Utilizar GitHub Actions para integração contínua.

---

# 6. Regras de Negócio

RN01

Toda tarefa deverá possuir um título.

RN02

Cada tarefa possuirá apenas um status.

RN03

Não será permitido cadastrar tarefas com título vazio.

RN04

A exclusão de uma tarefa será definitiva.

---

# 7. Restrições

- O projeto possui finalidade exclusivamente acadêmica.
- O desenvolvimento seguirá o escopo proposto pela disciplina.
- O sistema será executado localmente durante o desenvolvimento.

---

# 8. Critérios de Aceitação

O projeto será considerado concluído quando atender aos seguintes critérios:

- Sistema web funcionando corretamente.
- Operações CRUD implementadas.
- Repositório atualizado no GitHub.
- Histórico de commits documentando o desenvolvimento.
- GitHub Projects (Kanban) implementado.
- Testes automatizados executando corretamente.
- GitHub Actions configurado.
- Relatório técnico finalizado.
